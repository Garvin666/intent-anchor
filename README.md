# intent-anchor · 意图锚定

> 动手之前，先用**你自己的记忆库**把「用户嘴上说的」还原成「他真正要的」。
> 证据必须能指到 `路径:行号`；指不到的，一律标成 `[推断]` 而不是 `[记忆]`。

这是一个给 AI 编码助手用的 **skill**（技能）：一段 Markdown 指令 + 两个零依赖 Python 脚本。
它不产生新知识，只做一件事 —— **把靶心钉准再开枪**。

## 它解决什么问题

人给 AI 下指令时，常常只有一句话：

```
「修复这个」「无法打开」「弄一下」「继续」
```

对 AI 来说这不是需求，是谜面。常见两种失败：

- **猜**：把「弄一下」猜成某个具体动作，做完发现猜错了；
- **问**：把已经写在记忆里的事再问一遍，把一次对齐拖成五轮审讯。

本技能的立场是第三条路：**先查记忆库**。你自己攒下来的画像、交接记录、踩坑记录里，
大概率已经写着答案。查到的当依据，查不到才问，而且问不超过 3 条、每条带推荐项。

## 四个模式

| 模式 | 何时触发 | 产出 |
| --- | --- | --- |
| **M1 意图锚定** | 短指令 / 报错短语 / 截图当需求 / 指代不明 | 理解确认表（5 栏，每条依据标 `[记忆]`/`[推断]`/`[上下文]`） |
| **M2 追问去重** | 要素基本齐、只缺个别 | 空白清单（≤3 条，选项式，带推荐项与代价） |
| **M3 想法结构化** | 一次抛出多条互相抢资源的想法 | 命题卡（目标/约束/验收/风险/下一步） |
| **M4 未决提醒** | 任务刚交付、上下文已推进、无新指令 | ≤3 条**原文引用**（没有未决项就沉默） |

## 关于 M4：一个被实测推翻的功能

v1.0 的 M4 叫「下一步预判」—— 从记忆里猜用户接下来会做什么。听起来很有用，所以我去测了它。

157 例历史回放的结果：**top-1 精确率 7%，即使排序完美，上限也只有 20%**。
原因不复杂：记忆记的是「做过什么」，而明天的第一件事由外部输入决定（新指令、新报错、别人找你）。

所以 v1.1 把它改名成「未决提醒」，并且**只做引用不做生成**：把「刚结束那个任务」的记录里
还挂着的未决项**原文抄出来 + 行号**，要不要接由你定。详见 [`benchmarks/`](benchmarks/)。

这个否定结果是本仓库最值钱的部分之一 —— 它省掉了后续所有「再调调参数就好了」的弯路。

## 安装

```bash
git clone <this-repo> ~/.claude/skills/intent-anchor     # 或你所用助手的 skills 目录
```

把 `memory_probe.config.example.json` 复制成 `memory_probe.config.json`，改两处：

```jsonc
{
  "kb_root": "~/my-knowledge-base",       // 你的记忆库根目录
  "layers": [
    {"name": "画像", "weight": 1.5, "glob": "memory/profile/*.md"},
    {"name": "交接", "weight": 1.0, "glob": "memory/handoffs/**/*.md"}
  ],
  "resident": { "files": ["memory/profile/working-style.md"] }
}
```

`glob` 支持 `**/` 递归与 `*` 通配。层的名字随便起，`weight` 决定同名次的排序偏好
（稳定偏好 > 经验沉淀 > 流水日志）。

## 用法

```bash
S=scripts/memory_probe.py

# 常驻层：每次开工必读的那一小撮（建议控制在 500–700 行）
python $S pin --budget 700

# 检索层：按需命中，不整读
python $S probe --query "用户原话 + 我初步理解的关键词" --top 15

# 找同一任务记录里还挂着的未决项
python scripts/find_pending.py --task "刚结束的那个任务名"

# 校验文档里的 [记忆] 路径:行号 引用是否可解析
python scripts/verify_refs.py 报告.md --root ~/my-knowledge-base

# 自检：阳性 / 阴性 / 行号自洽 / 语义通道
python $S selftest
```

## 语义通道（可选）

字面通道切 2-gram / 3-gram，用户换个说法就召回不到（他说「弄一下」，记忆里写的是「改造」）。
如果你已经有本地检索引擎（向量或混合检索），可以在配置里接上，**不要为本工具重建一套索引**：

```jsonc
"semantic": {
  "enabled": true,
  "python": "/path/to/venv/python",
  "module": "your_engine",          // 以 `python -m <module> --root <kb> search <q> --json` 调用
  "module_home": "/path/to/src",    // 加进 PYTHONPATH
  "zone": "memory"
}
```

三条硬约定，写在 `SKILL.md` §3.5：

1. **行号必须回贴**。检索引擎返回的是 chunk，没有行号，而本技能的契约是 `路径:行号`。
   `locate_line` 拿 chunk 片段当锚点回贴（锚点 ≥14 字符、最长优先）；回贴失败的命中**不许引用**。
2. **降级必须出声**。没配就说「未配置」，配了跑不起来就说「不可用」并写明缺什么。
   静默降级是最坏的情况 —— 它把「没查」伪装成「查过了」。
3. **语义命中精度低**。能召回到字面没有的条目，但常常只是沾边。必须回读原文再决定引不引。

## 自检能验什么、不能验什么

`selftest` 做四段断言：阳性对照（自指查询）、阴性对照（乱码必须零命中）、
行号自洽（命中行必须落在报告的那一行）、语义通道（可用性 / 新增召回 / 行号回贴保真）。

它**验不了**「这条依据引对了没有」—— 那需要回读原文，没有机器 oracle。
`verify_refs.py` 同理，只验「路径存在 + 行号不越界」，不验内容。
